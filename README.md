Приложение на C# (Windows Forms) для локального планирования траекторий мобильного робота в среде со статическими и динамическими препятствиями на основе алгоритма Dynamic Window Approach (DWA).
Проект реализует полный цикл локальной навигации: от UDP-коммуникации с симулятором и приёма телеметрии в реальном времени до моделирования траекторий, их оценки по многокритериальной функции и отправки управляющих команд с учётом кинематических ограничений робота.
Основные возможности
Сетевое взаимодействие с симулятором: Приём телеметрии (координаты, курс, показания 8 дальномеров, энкодеры) по протоколу UDP в фоновом потоке с парсингом JSON без внешних зависимостей. Отправка управляющих команд в формате {N, M, F, B, T} с инкрементным счётчиком команд для контроля целостности пакетов.
Глобальная навигация по маршрутным точкам: Загрузка маршрута из текстового файла с поддержкой разделителей ,, ;, пробел и инвариантной культуры для корректного парсинга десятичных чисел. Автоматическое переключение между точками при достижении радиуса прибытия с зацикливанием маршрута через операцию взятия остатка.
Два режима управления: Алгоритм DWA с моделированием траекторий и простой П-регулятор для следования по маршруту с реакцией на близкие препятствия. Переключение между режимами через чекбокс в реальном времени без перезапуска.
Алгоритм DWA с динамическим окном: Построение окна допустимых скоростей с учётом текущих скоростей и максимальных ускорений, что гарантирует плавный разгон и ограничение приращения угловой скорости не более 0.2 рад/с за секунду. Моделирование траекторий на горизонте 2.0 секунды с шагом 0.1 секунды методом интегрирования Эйлера первого порядка.
Многокритериальная оценка траекторий: Формула Score = α·heading + β·clearance + γ·velocityScore с настраиваемыми весами. Компонент heading оценивает ориентацию робота на цель в конце траектории с нормализацией угловой ошибки в диапазон [0, 1]. Компонент clearance находит минимальное расстояние до препятствий с нелинейным штрафом (×0.3) при сближении ближе 40 см. Компонент velocityScore стимулирует движение на максимальной скорости со штрафом 0.5 для движения назад.
Память динамических препятствий: Преобразование показаний 8 дальномеров в мировые координаты точек касания с фильтрацией статических стен карты через IsNearStaticWall. Механизм слияния близких обнаружений (порог 0.7 м) для предотвращения дублирования. Временное «старение» объектов с удалением из памяти через 10 секунд после последнего наблюдения.
Аварийный режим (Recovery Behavior): Активация при отсутствии безопасных траекторий или скорости менее 5 см/с. Raycasting по карте в направлениях ±90° от курса для выбора стороны с большим свободным пространством. Запоминание направления манёвра на 1.5 секунды для предотвращения осцилляций.
Многоуровневая визуализация: Отрисовка статической карты из файла, глобального маршрута, корпуса робота с вектором курса, лучей дальномеров с точками обнаружения. Визуализация DWA: серый веер безопасных траекторий, красный пунктир коллизий, тепловая карта оценок (градиент от красного к зелёному через нормализацию Score), ярко-зелёная линия выбранной траектории, оранжевые маркеры препятствий с указанием возраста.
Ручное управление: Ползунки тяги (F) и баланса (B) в диапазоне [-100, 100], кнопки направлений (Вперёд/Назад/Лево/Право), управление с клавиатуры (WASD, стрелки, Space для стоп).
Реализованные алгоритмы
Динамическое окно скоростей (Dynamic Window)
Вместо перебора всех возможных скоростей робота алгоритм ограничивает поиск окном достижимых скоростей за один шаг времени:
v_min_dyn = max(-v_max·0.3, v_current - a_max·Δt)
v_max_dyn = min(v_max, v_current + a_max·Δt)
ω_min_dyn = max(-ω_max, ω_current - α_max·Δt)
ω_max_dyn = min(ω_max, ω_current + α_max·Δt)
Где Δt = 0.1 с — шаг дискретизации, a_max и α_max — максимальные ускорения с формы. Это гарантирует физическую реализуемость траекторий и плавность движения: при α_max = 0.2 рад/с² угловая скорость за 1 секунду изменится не более чем на 0.2 рад/с.
Моделирование траектории (SimulateTrajectory)
Интегрирование Эйлера первого порядка для предсказания положения робота:
x(t+Δt) = x(t) + v·sin(θ)·Δt
y(t+Δt) = y(t) + v·cos(θ)·Δt
θ(t+Δt) = θ(t) + ω·Δt
Горизонт планирования SimTime = 2.0 с с шагом TimeStep = 0.1 с генерирует 20 прогнозных точек. При максимальной скорости 0.4 м/с робот «видит» траекторию длиной 0.8 м вперёд.
Проверка коллизий (CheckCollision)
Бинарный фильтр для каждой из 20 точек траектории:
Статические стены: Вызов IsNearStaticWall с радиусом проверки RobotRadius + safetyMargin = 0.35 м. Метод вычисляет индексы строк/столбцов сетки (ячейка 0.25×0.25 м), которые могут пересекаться с кругом допуска, избегая перебора всей карты 64×40. Для каждой клетки-стены через clamping (Math.Max/Math.Min) находится ближайшая точка на границе прямоугольника, затем по теореме Пифагора вычисляется расстояние.
Динамические препятствия: Евклидово расстояние от центра траектории до центра препятствия сравнивается с суммой радиусов: dist < RobotRadius + ObstacleRadius + 0.02 = 0.62 м. Это гарантирует отсутствие физического касания корпусов.
Оценочная функция (CalculateClearance)
Поиск минимального расстояния minDist от любой точки траектории до любого препятствия (принцип «самого слабого звена»):
Дальномеры: Для каждой из 20 точек траектории вычисляются мировые координаты точек касания 8 лучей, затем расстояние до каждой точки.
Память препятствий: Расстояние считается до поверхности объекта: distToSurface = max(0, distToCenter - ObstacleRadius). Нелинейный штраф: если distToSurface < 0.40 м, эффективное расстояние уменьшается в 3.3 раза (×0.3), что заставляет алгоритм избегать узких проходов.
Нормализация: clearance = min(minDist / 3.0, 1.0), где 3.0 м — эталон полной безопасности (≈10 радиусов робота).
Направление к цели (CalculateHeading)
Оценка ориентации робота в конце траектории:
targetAngle = atan2(targetX - lastX, targetY - lastY)
error = targetAngle - finalTheta
Нормализация ошибки в диапазон [-π, π] через циклическое вычитание/прибавление 2π для обработки перехода через 360° (кратчайший путь поворота). Итоговая оценка: heading = 1.0 - |error| / π, где 1.0 — идеальное совпадение курса с направлением на цель.
Память динамических препятствий (UpdateDynamicObstacleMemory)
Для каждого из 8 дальномеров с показаниями в диапазоне 0.1–2.5 м:
Вычисление мировых координат точки касания:
sensorX = robotX + RobotRadius·sin(globalDirection)
edgeX = sensorX + distM·sin(globalDirection)
Фильтрация стен: IsNearStaticWall(edgeX, edgeY, 0.15) — если точка принадлежит стене карты, она игнорируется.
Вычисление предполагаемого центра препятствия: obsX = sensorX + (distM + ObstacleRadius)·sin(globalDirection).
Слияние: если в памяти есть объект на расстоянии < 0.7 м, обновляется его время жизни; иначе создаётся новая запись.
Удаление устаревших: объекты с LastSeen старше 10 секунд удаляются из списка.
Аварийный режим (Recovery Behavior)
При !foundSafeTrajectory || bestV < 0.05:
Raycasting в направлениях robotTheta ± π/2 методом GetDistanceToWall с шагом 0.05 м до 5.0 м.
Проверка режима объезда: isInAvoidance = (now - lastAvoidanceTime) < 1.5 с.
Если уже в манёвре — сохранение направления; иначе выбор стороны с большим пространством: turnDir = (leftDist > rightDist) ? 1.5 : -1.5.
Возврат (0.00, turnDir) — поворот на месте без линейного движения.
П-регулятор (альтернативный режим)
При выключенном DWA:
targetAngle = atan2(dx, dy)
errorAngle = targetAngle - currentTheta
errorDeg = errorAngle · 180 / π
Нормализация ошибки в [-180°, 180°]. Логика:
Если frontDistance < 50 см — отъезд назад (F = -30, B = 0).
Если |errorDeg| > 60° — поворот на месте (F = 0).
Иначе движение вперёд со скоростью, зависящей от дистанции: 60 (>2 м), 30 (>1 м), 15 (<1 м).
Поворот: B = -errorDeg · 1.5 с ограничением [-100, 100].
Технические детали
Единицы измерения
Алгоритм работает в системе СИ: расстояния в метрах, время в секундах, углы в радианах, скорости в м/с и рад/с. Исключения: максимальная скорость на форме в см/с (конвертируется делением на 100), показания дальномеров в см (конвертируются делением на 100), курс от симулятора в градусах (конвертируется умножением на π/180).
Формат UDP-пакетов
Приём от симулятора (JSON):
json
{"n":1234,"x":1.25,"y":2.50,"t":45.0,"d0":395,"d1":182,...,"d7":1220,"le":5000,"re":5100}
Отправка команд (JSON):
json
{"N":123,"M":0,"F":50,"B":-20,"T":0}
Где F — тяга [-100, 100], B — баланс/поворот [-100, 100]. Нормализация физических скоростей: F = (v / v_max) · 100, B = -(ω / ω_max) · 100 (минус для согласования знаков математики и симулятора).
Архитектура многопоточности
Приём данных в фоновом потоке (Thread с IsBackground = true) через UdpClient.Receive(). Безопасное обновление UI через this.Invoke((MethodInvoker)delegate { ... }). Таймер навигации tmrNavigation работает в основном потоке с интервалом 100 мс.

Оптимизация производительности
IsNearStaticWall проверяет только клетки в радиусе допуска, а не всю карту 64×40.
Тепловая карта рисуется через каждые 3 точки траектории для снижения нагрузки на GDI+.
Парсинг JSON реализован вручную через IndexOf/Substring без загрузки Newtonsoft.Json.
Траектории хранятся как List<(double x, double y)> (кортежи) для минимизации аллокаций.
